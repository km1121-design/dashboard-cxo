# Google アカウント認証の設定手順

メンバーごとに見える範囲を分けるための設定手順。所要 15〜20 分、作業は 3 箇所。

- **A. Google Cloud** — OAuth クライアント ID を発行する
- **B. Apps Script** — スクリプトプロパティを設定して再デプロイする
- **C. GitHub** — リポジトリ変数にクライアント ID を登録する

> **設定するまでは今までどおり動く。** `GOOGLE_CLIENT_ID` を設定した時点で
> Google サインインが必須になる。A → B → C の順に進めれば、切り替わるのは C を
> 反映（デプロイ）した瞬間だけになる。

---

## しくみ

```
ブラウザ                      GAS                         Google
  │ Google でサインイン
  │───────────────────────────────────────────────────────▶
  │ ◀── ID トークン（JWT・1時間有効）────────────────────────
  │
  │ 売上ログを要求（?idToken=…）
  │──────────────────────────▶
  │                            │ トークンを検証（tokeninfo）
  │                            │─────────────────────────▶
  │                            │ ◀── メールアドレス ──────────
  │                            │
  │                            │ メール → メンバーID → 役職
  │                            │ Manager なら自分の事業部の行だけに絞る
  │ ◀── 絞り込み済みの行 ───────│
```

要点は **絞り込みが GAS 側で行われる**こと。入舩・中原のブラウザには他事業部の行が
そもそも届かないので、開発者ツールや localStorage をいじっても全社の数字は見られない。

---

## A. Google Cloud で OAuth クライアント ID を発行する

1. https://console.cloud.google.com/ を開く（会社の Google アカウントで）
2. 画面上部のプロジェクト選択 →「新しいプロジェクト」
   - 名前: `gooner-dashboard` など
3. 左メニュー「APIとサービス」→「OAuth 同意画面」
   - User Type: **内部**（Google Workspace の場合。社外に配らないのでこれでよい）
     - 「内部」が選べない場合は「外部」を選び、テストユーザーにメンバーを追加する
   - アプリ名: `Gooner PL管理ポータル`
   - ユーザーサポートメール・デベロッパー連絡先: 自分のアドレス
   - スコープは追加不要（サインインだけで、Google のデータは読まない）
4. 左メニュー「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
   - アプリケーションの種類: **ウェブ アプリケーション**
   - 名前: `dashboard-cxo`
   - **承認済みの JavaScript 生成元** に次を追加（末尾のスラッシュは付けない）:
     ```
     https://km1121-design.github.io
     http://localhost:5173
     ```
     （2 つ目はローカル開発用。不要なら省いてよい）
   - 承認済みのリダイレクト URI は**空のままでよい**（この方式では使わない）
5. 発行された **クライアント ID**（`…….apps.googleusercontent.com`）を控える

> クライアント ID は公開される値。HTML に埋め込まれても問題ない
> （秘密にするのはクライアント シークレットの方で、この構成では使わない）。

## B. Apps Script 側の設定

### B-1. コードを最新にする

`gas/Code.gs` の内容を Apps Script エディタに貼り付ける
（GitHub Actions の「Deploy GAS」ワークフローを使っている場合は自動で反映される）。

### B-2. スクリプトプロパティを設定する

Apps Script エディタ → 左メニュー「プロジェクトの設定」（歯車）→「スクリプト プロパティ」

| プロパティ | 値 | 必須 |
| --- | --- | --- |
| `GOOGLE_CLIENT_ID` | A で控えたクライアント ID | ✅ これを入れると Google 認証が有効になる |
| `MEMBER_EMAILS` | 下記の JSON | ✅ |
| `ALLOWED_HD` | `gooner.space` | 任意（社外アカウントを弾く） |

`MEMBER_EMAILS` は **メールアドレス → メンバーID** の対応。1 行の JSON で入れる:

```json
{"irifune@gooner.space":"M001","nakahara@gooner.space":"M002","mita@gooner.space":"M003","km1121@gooner.space":"M004"}
```

メンバーIDは `src/constants/master.ts` と同じ:

| ID | 氏名 | 事業部 | 役職 | 見える範囲 |
| --- | --- | --- | --- | --- |
| M001 | 入舩 雄志 | イベント営業 | Manager | 自分の事業部＋BAR の行 |
| M002 | 中原 聖人 | 人材 | Manager | 自分の事業部＋BAR の行 |
| M003 | 三田 航大 | 物流・バックヤード | Admin | 全社 |
| M004 | u s | 本部 | Admin | 全社 |

> BAR（店舗運営(BAR)）の行だけは事業部を問わず全員に返している。
> 中原氏の「他部紹介 BAR売上10%」の計算に必要なため。店舗の売上行で、
> 個人が特定される情報は含まない。

### B-3. 外部リクエストの承認

トークン検証で Google に問い合わせるため、外部リクエストの権限が要る。
エディタで `generateAuthToken` などの関数を一度手動実行し、権限の確認画面が出たら承認する。

### B-4. 再デプロイ

デプロイ →「デプロイを管理」→ 既存のデプロイの鉛筆アイコン → バージョン「新バージョン」→ デプロイ。
**URL は変わらない**（新しいデプロイを作ると URL が変わるので、既存デプロイの更新にすること）。

## C. GitHub 側の設定

リポジトリ → Settings → Secrets and variables → Actions → **Variables** タブ → New repository variable

| 変数名 | 値 |
| --- | --- |
| `VITE_GOOGLE_CLIENT_ID` | A で控えたクライアント ID |
| `VITE_GOOGLE_HD` | `gooner.space`（任意。サインイン候補を自社ドメインに絞る） |

登録したら Actions → 「Deploy to GitHub Pages」→ Run workflow で反映する
（main への push でも反映される）。

## 動作確認

1. https://km1121-design.github.io/dashboard-cxo/ を開く → サインイン画面が出る
2. 入舩さんのアカウントでサインイン → 個人ビューだけが表示される
3. 開発者ツール → Application → Local Storage を消しても、リロード後もやはり個人ビュー
   （閲覧範囲はブラウザではなくサーバーが決めているため）
4. 管理者アカウントでサインイン → 全社ダッシュボードが表示される

うまくいかないときは:

| 症状 | 原因と対処 |
| --- | --- |
| サインイン画面が出ずに全社ビューが出る | `VITE_GOOGLE_CLIENT_ID` が反映されていない。Actions のビルドログで環境変数を確認 |
| 「GAS 側が Google 認証に対応していません」と出る | B-1 / B-2 が未実施、または B-4 の再デプロイ漏れ |
| 「このアプリ向けの認証情報ではありません」 | A のクライアント ID と B-2 の `GOOGLE_CLIENT_ID` が食い違っている |
| 「…は利用者として登録されていません」 | `MEMBER_EMAILS` にそのメールアドレスが無い。大文字小文字は無視されるが、綴りは要確認 |
| ボタンが出ない・押しても何も起きない | A-4 の「承認済みの JavaScript 生成元」にアクセス元のドメインが入っているか確認 |

## 運用上の注意

- **サインインは 1 時間で切れる。** 切れると自動でサインイン画面に戻る。同じブラウザで
  Google にログインしたままなら、多くの場合は押すだけで通る。
- **ID トークンは sessionStorage に置く。** タブを閉じれば消えるので、共有端末でも
  開きっぱなしにならない。
- **メンバーが増減したら** `MEMBER_EMAILS` と、必要なら `gas/Code.gs` の
  `MEMBER_DIRECTORY` / `src/constants/master.ts` を更新する。
- **元に戻したいとき** はスクリプトプロパティの `GOOGLE_CLIENT_ID` を削除すれば、
  従来の合言葉（`AUTH_TOKEN`）運用に戻る。フロント側も `VITE_GOOGLE_CLIENT_ID` を消す。
- ID トークンは GET のクエリに載せて送っている。GAS の実行ログに URL が残るため、
  ログを共有するときは伏せること。
